# PyReeler v0.1 Milestone Validation

**Date:** 2026-07-12
**Result:** Product milestone complete

## Artifact proof

The final validation built a wheel, installed `pyreeler[tui]` into a temporary
virtual environment outside the checkout, removed `PYTHONPATH`, and ran all
checks from a separate working directory.

Verified:

- `python -m pyreeler list`;
- `python -m pyreeler info lorenz`;
- `import pyreeler.engine` from the installed artifact;
- installed `pyreeler/tui/styles.tcss`;
- a headless Textual launch that mounted the no-argument TUI;
- a one-second 160x120, 4-fps Lorenz render using system FFmpeg; and
- the same render with system FFmpeg hidden, using the declared
  `imageio-ffmpeg` binary.

The system render produced a 10,547-byte MP4. The fallback render produced a
5,655-byte MP4.

## Streaming proof

`render_film()` now passes the ordered frame iterator directly to FFmpeg.
Focused tests prove that it does not hand the encoder a list, retains at most the
current frame during a sequential render, reports progress in order, closes the
frame iterator, reaps FFmpeg after frame-generation errors, and surfaces FFmpeg
stderr after a broken pipe.

Focused engine and resolver validation: 9 tests passed.

## Repository checks

- `python sync.py --check`: passed.
- `git diff --check`: passed.
- Clean installed-wheel smoke with both FFmpeg sources: passed.
- Full local legacy suite: 100 passed, 10 failed.

The ten full-suite failures predate the streaming change and fall outside the
v0.1 product boundary: Windows home/path assumptions, graduation-manifest policy,
TUI tests that assume Lorenz is the initially sorted recipe, a simulated Linux
path assertion executed on Windows, and an optional-WGPU environment assumption.
They remain visible follow-up work rather than being hidden or folded into this
milestone.

## Deliberate exclusions

PyInstaller binary bundling is not a v0.1 guarantee. Documentation labels the
command as a development starting point and requires target-system FFmpeg
verification. Frame streaming did not change encoder selection, worker ordering,
recipe behavior, or progress presentation.
