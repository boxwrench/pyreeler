# v0.1 Release-Boundary Agent Batch

**Date:** 2026-07-12
**Status:** Ready for agentic implementation
**Parent:** [Current working plan](CURRENT.md)

## Batch outcome

Complete the first two v0.1 milestone tasks as sequential, independently
reviewable commits:

1. Prove and repair the installed-wheel boundary.
2. Make the promised FFmpeg fallback consistent across supported entry points.

Do not begin frame streaming, graduation-gate removal, banner consolidation, GPU
detection changes, or unrelated cleanup.

## Execution contract

- Work one task at a time, in order.
- Begin each task with its focused reproducer.
- Prefer the smallest correction supported by the failing artifact test.
- Do not preserve checkout behavior with another path mutation.
- Keep separate commits so either task can be reverted independently.
- Preserve provider self-containment and the synchronization check.

## Task 1: Prove and Repair the Installed-Wheel Boundary

### Goal

A wheel installed into a clean environment outside the checkout can import the
renderer, use the CLI, find TUI styles, and render a short MP4.

### Confirmed evidence

- Project metadata explicitly packages only the three pyreeler packages.
- The engine imports root-level templates.video modules.
- The TUI loads styles.tcss, but no package-data rule declares it.
- Package initialization adds the checkout parent to the import path.
- Unit tests also add the repository root to the import path.

### Deliverables

- Add an artifact smoke test that builds a wheel, creates a clean environment
  outside the checkout, installs only the wheel and declared dependencies, and
  changes the working directory away from the checkout.
- From that environment, verify list, info, engine import, stylesheet presence, and
  a one-second 160x120 4-fps Lorenz render when FFmpeg is available.
- Configure setuptools so all local CLI/TUI runtime modules belong to the artifact.
- Include styles.tcss as package data.
- Remove or narrow the package checkout-path mutation once runtime imports are owned
  by the artifact. Do not break repository-only experimental imports.
- Add the artifact smoke to CI as a distinct step or job.
- Document the supported wheel install separately from editable development installs.

### Boundaries

- Do not reorganize every template or create a plugin/resource framework.
- Do not refactor rendering behavior.
- Do not make TUI dependencies mandatory for CLI-only users unless proven necessary.
- Verify the TUI resource without leaving CI waiting for interactive input.

### Acceptance

Run the full tests, synchronization check, graduation check, and build. Then, from
outside the checkout using only the installed wheel:

- run pyreeler list;
- run pyreeler info lorenz;
- import pyreeler.engine;
- resolve the installed stylesheet;
- render a one-second low-resolution MP4; and
- confirm the MP4 exists and is non-empty.

### Commit

Prove installed wheel runtime boundary

## Task 2: Align FFmpeg Fallback and Installation Behavior

### Goal

Every supported path either has the advertised imageio-ffmpeg fallback or clearly
requires system FFmpeg. For v0.1, prefer making the existing automatic-fallback
promise true for the local renderer.

### Confirmed evidence

- The shared resolver already prefers system FFmpeg and falls back to imageio-ffmpeg.
- The non-TUI engine uses that resolver.
- imageio-ffmpeg is declared only in the TUI extra.
- Both requirements files omit it while README promises automatic fallback.
- The skill installer exits when system FFmpeg is absent.
- CI uses a manually duplicated dependency list.

### Deliverables

- Declare imageio-ffmpeg in the dependency tier used by every local render path that
  promises fallback; remove narrower duplicate declarations where appropriate.
- Make both requirements files, project metadata, installers, and README agree.
- Update install.sh so missing system FFmpeg does not contradict the fallback
  policy. Report the selected source and fail only if neither source resolves after
  dependency installation.
- Add focused resolver tests: explicit path wins, system PATH wins, Python fallback
  wins when PATH is empty, and neither source gives a useful error.
- Avoid downloads during unit tests by mocking resolver boundaries.
- Make the artifact CI smoke install declared project dependencies rather than
  relying solely on a hand-maintained dependency list.
- Limit PyInstaller documentation to verified behavior. Mark binary bundling manual
  if the current command is not proven in this batch.

### Boundaries

- Preserve system FFmpeg preference, encoder smoke tests, and software fallback.
- Do not simplify hardware detection or add another resolver.
- Do not change frame buffering or progress behavior.

### Acceptance

Run the full tests, synchronization check, graduation check, and build. In clean
environments outside the checkout:

1. With system FFmpeg present, verify it is selected and a short render succeeds.
2. With system FFmpeg hidden from PATH, verify the declared Python fallback resolves
   and a short render succeeds.

Exercise the CLI installer on POSIX or test its non-interactive decision logic with
an isolated harness.

### Commit

Align FFmpeg fallback dependencies
